# وب‌سایت دبیرستان دوره دوم امام امیرالمؤمنین (ع)

سایت رسمی مدرسه با **HTML5 + CSS3 + JavaScript خام** در سمت مرورگر، **Node.js (Express)** در سمت سرور و **SQLite** به عنوان دیتابیس. تمام محتوای سایت، تنظیمات، اخبار، گالری، کادر مدرسه، افتخارات و درخواست‌های پیش‌ثبت‌نام در دیتابیس ذخیره می‌شوند و از پنل مدیریت `/admin` قابل ویرایش هستند.

> این پروژه یک نمونه نمایشی نیست: فرم پیش‌ثبت‌نام واقعاً در دیتابیس ثبت می‌شود، پنل مدیریت با احراز هویت محافظت می‌شود و تغییرات مدیر با ذخیره شدن در دیتابیس، بلافاصله در سایت عمومی دیده می‌شود.

---

## ۱. امکانات پروژه

**سایت عمومی (فارسی، راست‌به‌چپ، واکنش‌گرا)**

- صفحه اصلی با بخش‌های: هدر و منوی ناوبری، بخش معرفی (Hero)، معرفی مدرسه، پایه‌های تحصیلی، رشته‌های تحصیلی، کادر مدیریتی و دبیران، افتخارات، اخبار و اطلاعیه‌ها، گالری تصاویر، پرسش‌های متداول، تماس با مدرسه و فوتر.
- صفحه‌های داخلی: معرفی مدرسه، پایه‌ها، رشته‌ها، اخبار با صفحه جزئیات خبر، کادر، گالری، افتخارات، پرسش‌های متداول، ارتباط با ما، پیش‌ثبت‌نام، پیگیری پیش‌ثبت‌نام، ورود کاربران و درخواست‌های من.
- همه محتوای صفحه‌ها از API خوانده می‌شود؛ هیچ متن تزئینی یا داده ساختگی در قالب HTML ثابت نشده است.
- بخش‌هایی که مدیر هنوز داده‌ای در آن‌ها وارد نکرده است، پیام «تکمیل نشده» نشان می‌دهند و هیچ اطلاعات جعلی نمایش داده نمی‌شود.

**سامانه پیش‌ثبت‌نام**

- فرم با اعتبارسنجی دو مرحله‌ای (مرورگر + سرور).
- ذخیره واقعی در دیتابیس و تولید **کد پیگیری غیرقابل حدس** (`SW-XXXXX-XXXXX`).
- پیگیری وضعیت با کد پیگیری + شماره موبایل (بدون افشای اطلاعات برای دیگران).
- مدیریت درخواست‌ها در پنل: فهرست، جست‌وجو، فیلتر بر اساس وضعیت، جزئیات، تغییر وضعیت (جدید/در حال بررسی/تأییدشده/ردشده)، بایگانی، یادداشت داخلی، حذف با نقش مدیر ارشد و خروجی CSV.
- محدودیت تعداد ثبت از هر آی‌پی و جلوگیری از ثبت تکراری.

**پنل مدیریت `/admin`**

- داشبورد آماری واقعی: بازدید سایت، تعداد و وضعیت درخواست‌های پیش‌ثبت‌نام، اخبار منتشرشده، تصاویر گالری، کادر، افتخارات و نمودار ۷ روز گذشته.
- مدیریت کامل محتوا با ایجاد، ویرایش، حذف، فعال/غیرفعال‌سازی، انتشار و ترتیب‌گذاری: پایه‌ها، رشته‌ها، کادر مدرسه، اخبار، اطلاعیه‌ها، افتخارات، گالری، پرسش‌های متداول.
- مدیریت اطلاعات مدرسه (نام، شعار، معرفی، نشانی، تلفن، ایمیل، شبکه‌های اجتماعی، تصویر و متن بخش اصلی، لوگو).
- تنظیمات عمومی سایت و نمایش/پنهان‌سازی بخش‌ها و باز/بسته کردن فرم پیش‌ثبت‌نام.
- تنظیمات پیامک با قابلیت آزمایش اتصال، مدیریت کاربران، مدیریت حساب مدیران (فقط نقش «مدیر ارشد»)، تغییر رمز عبور و گزارش رویدادهای امنیتی.
- بارگذاری تصویر با کنترل نوع، حجم و پسوند و ساخت نام فایل امن توسط سرور.

**احراز هویت و امنیت**

- ورود مدیران با نام کاربری و رمز عبور؛ ذخیره رمز به‌صورت هش **bcrypt** (۱۲ راند).
- ورود کاربران با شماره موبایل و کد یک‌بارمصرف پیامکی (HMAC-SHA256 برای ذخیره کد، اعتبار زمانی، محدودیت تلاش و ارسال مجدد).
- نشست‌های مبتنی بر دیتابیس با شناسه تصادفی ۳۲ بایتی (فقط هش در دیتابیس)، کوکی `HttpOnly` + `Secure` در HTTPS + `SameSite`، و توکن CSRF برای همه درخواست‌های تغییردهنده.
- محافظت در برابر SQL Injection (همه کوئری‌ها با prepared statement)، XSS (بدون درج HTML از داده کاربر)، CSRF، Brute Force و ارسال انبوه.
- هدرهای امنیتی با Helmet و CSP سخت‌گیر، محدودیت نرخ درخواست روی APIها، لاگ رویدادهای امنیتی بدون ثبت رمز/کد/کلید، و مدیریت خطای بدون افشای Stack Trace در محیط عملیاتی.

## ۲. پیش‌نیازها

- **Node.js نسخه ۱۸.۱۷ یا بالاتر** (تست‌شده روی Node.js 22). نسخه‌های پیشنهادی: `20.x` یا `22.x`.
- npm نسخه ۹ یا بالاتر.
- در ویندوز برای کامپایل ماژول دیتابیس، در صورت نبود باینری آماده: `python3`، `make` و یک کامپایلر C++ (Build Tools).
- فضای نوشتن روی مسیر `storage/` (دیتابیس و پشتیبان‌ها) و `public/uploads/` (تصاویر بارگذاری‌شده).

بررسی نسخه:

```bash
node -v
npm -v
```

## ۴. تنظیم فایل `.env`

```bash
cp .env.example .env
```

سپس مقادیر این کلیدها را تعیین کنید (توضیح کامل در `.env.example`):

| کلید | توضیح |
| --- | --- |
| `NODE_ENV` | در سرور واقعی `production` بگذارید (فعال شدن کوکی `Secure` و پنهان شدن جزئیات خطا). |
| `PORT` | پورت اجرای برنامه (پیش‌فرض ۳۰۰۰؛ روی cPanel معمولاً خود هاست مقدار می‌دهد). |
| `SESSION_SECRET` | **الزامی.** کلید تصادفی بلند برای هش کد پیامکی و امضای داده‌ها. |
| `ADMIN_SETUP_TOKEN` | توکن یک‌بارمصرف برای ساخت اولین مدیر در `/admin/setup`. |
| `SETUP_DISABLED` | پس از ساخت مدیر اولیه، `1` بگذارید تا مسیر نصب کاملاً بسته شود. |
| `DB_PATH` | مسیر فایل دیتابیس؛ **باید بیرون از `public/` باشد** (پیش‌فرض `./storage/school.db`). |
| `UPLOAD_DIR` | مسیر تصاویر عمومی (پیش‌فرض `./public/uploads`). |
| `COOKIE_SECURE` | در HTTPS مقدار `1`. |
| `SMS_PROVIDER` / `SMS_API_KEY` / `SMS_SENDER` | تنظیمات سرویس پیامک (می‌تواند خالی بماند و از پنل مدیریت وارد شود). |

ساخت کلید تصادفی:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

**هرگز مقدار واقعی کلیدها را در `.env.example`، مخزن گیت یا فایل‌های عمومی قرار ندهید.**

## ۵. راه‌اندازی دیتابیس و ساخت جداول

ساختار جداول به‌صورت **خودکار** در اولین اجرای برنامه ساخته می‌شود. برای اجرای دستی:

```bash
npm run migrate   # اجرای migration‌ها + درج داده‌های ساختاری اولیه
npm run seed      # فقط درج داده‌های اولیه (پایه‌ها، رشته‌ها، پرسش‌های متداول)
```

جدول‌های ایجاد‌شده: `admins`، `users`، `sessions`، `site_settings`، `school_info`، `grades`، `study_fields`، `staff`، `news`، `announcements`، `achievements`، `gallery`، `faqs`، `pre_registrations`، `sms_settings`، `otp_requests`، `audit_logs`، `page_views` و `migrations`.

داده‌های اولیه فقط شامل اطلاعات ساختاری است: نام مدرسه، پایه‌های دهم/یازدهم/دوازدهم، رشته‌های علوم تجربی، ریاضی و فیزیک، ادبیات و علوم انسانی و سه پرسش فرایندی درباره پیش‌ثبت‌نام. **هیچ نام، شماره تماس، خبر یا افتخار ساختگی درج نمی‌شود.**

## ۶. ساخت امن حساب مدیر اولیه

دو روش امن (رمز پیش‌فرض ثابت وجود ندارد):

**روش اول — خط فرمان (پیشنهادی روی سرور):**

```bash
node scripts/create-admin.js --username admin --name "نام مدیر" --password "یک-رمز-قوی-با-حرف-و-رقم"
```

یا بدون ثبت رمز در تاریخچه پوسته:

```bash
ADMIN_PASSWORD="رمز-قوی" node scripts/create-admin.js --username admin --name "نام مدیر"
```

**روش دوم — صفحه نصب یک‌باره:**

1. در `.env` مقدار `ADMIN_SETUP_TOKEN` را تعیین و سرور را اجرا کنید.
2. به `/admin/setup` بروید و توکن نصب، نام کاربری و رمز عبور را وارد کنید.
3. پس از ساخت اولین مدیر، این صفحه به‌صورت خودکار غیرفعال می‌شود. برای اطمینان بیشتر `SETUP_DISABLED=1` بگذارید.

قواعد رمز عبور: حداقل ۱۰ نویسه و شامل حرف و رقم. نام کاربری: ۳ تا ۶۰ نویسه لاتین، رقم، نقطه، خط تیره یا زیرخط.

## ۱۰. تنظیم سرویس پیامکی

ورود با کد یک‌بارمصرف به یک حساب فعال پیامکی نیاز دارد. ساختار سرویس ماژولار است و ارائه‌دهندگان زیر پشتیبانی می‌شوند:

| ارائه‌دهنده | مقدار `provider` | اطلاعات لازم |
| --- | --- | --- |
| کاوه‌نگار | `kavenegar` | کلید API و شماره فرستنده |
| ملی‌پیامک | `melipayamak` | نام کاربری، رمز/کلید API و شماره فرستنده |
| آی‌پی‌پنل | `ippanel` | کلید API و شماره فرستنده |
| حالت توسعه | `log` | بدون اعتبارنامه؛ پیامک واقعی ارسال نمی‌شود و کد در لاگ سرور ثبت می‌شود |

دو راه تنظیم:

1. **پنل مدیریت → تنظیمات پیامک (`/admin/sms`)**: انتخاب ارائه‌دهنده، وارد کردن کلید، شماره فرستنده و متن پیامک (`{code}` جای کد قرار می‌گیرد) و دکمه «آزمایش اتصال».
2. **متغیرهای محیطی**: `SMS_PROVIDER`، `SMS_API_KEY`، `SMS_USERNAME`، `SMS_SENDER`، `SMS_OTP_TEMPLATE`. متغیرهای محیطی بر تنظیمات دیتابیس اولویت دارند.

نکات امنیتی:

- کلید API فقط در سرور نگهداری می‌شود؛ در پاسخ‌های API به‌صورت ماسک‌شده بازمی‌گردد و هرگز در HTML/JS مرورگر قرار نمی‌گیرد.
- اگر اعتبارنامه تنظیم نشده باشد، **هیچ کدی ساخته نمی‌شود** و پیام صادقانه «ارسال پیامک فعال نیست» نمایش داده می‌شود؛ هیچ موفقیت ساختگی گزارش نمی‌شود.
- `SMS_PROVIDER=log` فقط برای اجرای محلی و آزمون است؛ در سرور واقعی استفاده نکنید.

## ۱۱. استقرار روی هاست cPanel دارای پشتیبانی Node.js

**پیش از هر چیز پشتیبانی هاستینگ را بررسی کنید.** این پروژه به این قابلیت‌ها نیاز دارد:

- ابزار **Setup Node.js App** در cPanel (اجرای برنامه‌های Node.js).
- امکان انتخاب نسخه Node.js (۱۸.۱۷ یا بالاتر).
- امکان اجرای `npm install` روی سرور و نصب وابستگی‌های بومی یا دسترسی به باینری‌های آماده.
- امکان تعیین فایل راه‌انداز (Application startup file)، متغیرهای محیطی و مسیر پوشه.
- امکان مدیریت فرایند (Restart) و پشتیبانی از HTTPS دامنه.

مراحل:

1. در cPanel → **Setup Node.js App** → **Create Application**.
2. نسخه Node.js را ۲۰ یا ۲۲، پوشه برنامه را مسیر پروژه و فایل راه‌انداز را `server/app.js` تعیین کنید.
3. **Application URL**: دامنه مدرسه را انتخاب کنید. برای اینکه فایلی از پوشه `storage/` قابل دانلود نباشد، **Document Root را روی پوشه `public/` تنظیم کنید** (اگر هاست اجازه نمی‌دهد، پروژه را در مسیری بیرون از `public_html` قرار دهید و از طریق فایل راه‌انداز سرو کنید).
4. در بخش Environment Variables این مقادیر را وارد کنید: `NODE_ENV=production`، `SESSION_SECRET`، `ADMIN_SETUP_TOKEN`، `DB_PATH=/home/USER/school-website/storage/school.db`، `UPLOAD_DIR=/home/USER/school-website/public/uploads`، `COOKIE_SECURE=1` و تنظیمات پیامک.
5. روی **Run NPM Install** بزنید، سپس **Run JS script** → `scripts/migrate.js` را اجرا کنید (یا یک‌بار `npm run migrate`).
6. حساب مدیر را بسازید: در Terminal cPanel یا از طریق `Run JS script` اسکریپت `scripts/create-admin.js` را با آرگومان‌ها اجرا کنید، یا صفحه `/admin/setup` را با توکن نصب باز کنید.
7. برنامه را **Restart** کنید و `/api/health` را بررسی کنید.

**اگر هاست شما فقط PHP و MySQL دارد و امکان اجرای Node.js نمی‌دهد:**

> این پروژه روی چنین هاستی اجرا **نمی‌شود**. Node.js زبان و محیط اجرای بک‌اند این پروژه است و SQLite نیز نیاز به دسترسی نوشتن روی فایل دارد. در این حالت باید هاستی با پشتیبانی Node.js انتخاب شود یا برنامه روی یک سرور/VPS یا سرویس میزبانی Node.js اجرا و دامنه به آن متصل شود. برای اطلاعات بیشتر با پشتیبانی هاست تماس بگیرید.

## ۱۲. تنظیم دامنه و HTTPS

1. دامنه را در DNS به IP هاست متصل کنید و در cPanel دامنه را به برنامه Node.js اختصاص دهید.
2. گواهی SSL را از **SSL/TLS Status** سی‌پنل (Let's Encrypt) فعال کنید و **Force HTTPS Redirect** را روشن کنید.
3. در `.env` مقادیر `COOKIE_SECURE=1` و `TRUST_PROXY=1` را قرار دهید تا کوکی نشست با پرچم `Secure` ارسال شود و آی‌پی واقعی بازدیدکننده ثبت شود.
4. پس از فعال بودن HTTPS، صفحه ورود پنل و فرم پیش‌ثبت‌نام را آزمایش کنید.

## ۱۳. مجوزهای فایل و پوشه

```bash
find . -type d -exec chmod 755 {} \;
find . -type f -exec chmod 644 {} \;
chmod 755 scripts/*.js
chmod 600 .env
chmod 700 storage storage/backups
chmod 755 public/uploads
```

- مالکیت فایل‌ها باید متعلق به کاربر اجرای برنامه باشد (در cPanel معمولاً نام کاربری حساب).
- فایل `.env` و پوشه `storage/` نباید از اینترنت قابل دسترسی باشند.
- پوشه `public/uploads/` باید قابل نوشتن باشد تا بارگذاری تصویر کار کند.

## ۱۴. پشتیبان‌گیری و بازیابی دیتابیس SQLite

**پشتیبان‌گیری (بدون توقف سرور):**

```bash
npm run backup
# فایل پشتیبان در storage/backups/school-<زمان>.db ساخته می‌شود
```

**بازیابی:**

```bash
npm run restore -- --file storage/backups/school-2026-01-01T00-00-00-000Z.db
# پیش از جای‌گزینی، از دیتابیس فعلی به‌طور خودکار پشتیبان گرفته می‌شود
```

نکات:

- فایل‌های `school.db`، `school.db-wal` و `school.db-shm` با هم متعلق به یک دیتابیس‌اند؛ برای پشتیبان‌گیری دستی، ابتدا برنامه را متوقف یا از اسکریپت بالا استفاده کنید.
- برای پشتیبان‌گیری خودکار در cPanel می‌توانید یک Cron Job روزانه برای `node scripts/backup.js` تنظیم کنید و فایل‌های `storage/backups/` را به فضای ابری منتقل کنید.
- تصاویر بارگذاری‌شده در `public/uploads/` نیز باید در پشتیبان‌گیری لحاظ شوند.

## ۱۶. چک‌لیست امنیتی پیش از انتشار عمومی

- [ ] `NODE_ENV=production` و `SESSION_SECRET` تصادفی و بلند تعیین شده است.

- [ ] HTTPS فعال و `COOKIE_SECURE=1` است.
- [ ] کلیدهای API پیامک فقط در سرور/متغیرهای محیطی قرار دارند و در مخزن گیت نیستند.
- [ ] `.env` در `.gitignore` است و هیچ Secret در مخزن کامیت نشده است.
- [ ] سرویس پیامک با دکمه «آزمایش اتصال» بررسی و متن پیامک نهایی شده است.
- [ ] اطلاعات واقعی مدرسه از پنل مدیریت تکمیل و بازبینی شده است (نشانی، تلفن، ایمیل، کادر، اخبار).
- [ ] آزمایش‌ها (`npm test`) و بررسی یک‌باره دسترسی غیرمجاز به `/api/admin/*` انجام شده است.
- [ ] پشتیبان‌گیری خودکار و روش بازیابی آزمایش شده است.
- [ ] وابستگی‌ها با `npm audit` بررسی شده‌اند.

> هیچ سامانه‌ای «کاملاً نفوذناپذیر» نیست. امنیت این پروژه با پیاده‌سازی و آزمایش کنترلها ارزیابی شده است، اما پیش از انتشار عمومی، بازبینی نهایی توسط یک متخصص امنیت توصیه می‌شود.

## ۱۷. عیب‌یابی

| مشکل | بررسی و راه‌حل |
| --- | --- |
| برنامه بالا نمی‌آید | خروجی `npm start` را ببینید؛ خطای `SESSION_SECRET` یعنی کلید تعیین نشده و خطای `SQLITE_CANTOPEN` یعنی مسیر دیتابیس اشتباه است. |
| صفحه‌ها باز می‌شوند اما محتوا خالی است | `/api/health` و `/api/site` را بررسی کنید؛ خطای ۵۰۰ معمولاً به دیتابیس یا مجوز پوشه مربوط است. |
| درخواست‌های پنل با خطای «درخواست نامعتبر» رد می‌شوند | کوکی‌های مرورگر را پاک کنید؛ توکن CSRF همراه کوکی ارسال می‌شود و با پاک شدن کوکی باید صفحه را دوباره بارگذاری کنید. |
| ورود مدیر انجام نمی‌شود | نام کاربری و رمز را بررسی کنید، محدودیت تلاش (۱۵ دقیقه) را در نظر بگیرید و `audit_logs` را در بخش «گزارش رویدادها» ببینید. |
| ورود با کد پیامکی کار نمی‌کند | در `/admin/sms` وضعیت را ببینید؛ تا زمانی که ارائه‌دهنده و اعتبارنامه تنظیم نشود، هیچ کدی ارسال نمی‌شود. |
| پیامک ارسال نمی‌شود | اعتبار حساب ارائه‌دهنده، شماره فرستنده تأییدشده و متن پیامک را بررسی کنید و «آزمایش اتصال» را اجرا کنید. |
| بارگذاری تصویر خطا می‌دهد | حجم فایل (پیش‌فرض حداکثر ۳ مگابایت)، قالب (JPG/PNG/WEBP) و قابل نوشتن بودن `public/uploads/` را بررسی کنید. |
| روی هاست اجرا نمی‌شود | بخش ۱۱ را ببینید؛ هاست باید از Node.js پشتیبانی کند. |
